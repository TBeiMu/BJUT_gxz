# 资费断网保留修复验证

日期：2026 年 11 月 20 日。用户反馈 v0.5.7／38 资费修订在断开 WiFi 后立即清空，无法继续查看最近结果。基线为发布记录提交 `b2ef0d9`；本次修复属于同一资费缓存修订，沿用用户“仍发布为 0.5.7”的授权，验证后替换同一 Release 的三个附件及说明，不改变版本、固定签名或原标签。此处为检查及发布进行中的记录，最终结果按实际补齐。

## 原因与修复范围

此前 `wifiChanged` 在非首次网络变化时调用 `reset(clearData = true)`，同时清空内存显示并删除单条缓存。原断网／换网回归也沿用了旧清空预期，没有检查“离线继续保留最近成功结果”这一用户实际需求。

本次改为同账号网络变化调用 `reset(clearData = false, queryFailed = false)`。断开、重连或切换 WiFi 仍递增查询代次、取消请求、关闭旧会话，清除 Cookie／验证码／网页／注销确认及诊断，禁用设备注销；最近成功的四项资费、设备显示信息、原查询时间及单条磁盘缓存继续保留。网络提示替换旧的通用查询失败标记；已经确认或尚未确认的注销结果仍优先显示，不能被普通断网提示掩盖。

缓存归属账号，而临时查询会话归属当前 WiFi；网络变化不再使已经成功取得的历史缓存读写失效。旧网络的在途查询仍按原任务代次丢弃，不能覆盖保留值或后续新成功结果。账号切换、编辑、账号存储失效、身份不符、明确会话失效及注销提交前清理规则保持。

不增加自动查询次数、失败重试、移动数据访问、后台任务、文件或保存条数。仍只有一条最多 32KiB 的缓存，恢复设备只读；当前有效查询成功后才重新开放设备操作。同次前台已经尝试过查询时，重连／换网不会额外自动重试。

## 验证设计

- JVM 更新旧断网清空断言，新增前台断开→重连／换网→新成功覆盖、断网后重建控制器恢复、排队历史读写保留、旧网络无视取消的迟到响应丢弃及注销中断网提示优先的回归。账号编辑／切换、失效清除和注销安全检查继续保留。
- Android 生命周期回归使用真实运行时及 WiFi 监听，在指定隔离模拟器执行真实 `svc wifi disable/enable`。前台断开／重连和后台暂停监听期间断网返回，均检查旧资费／设备／时间保留、会话关闭、注销入口无效、无额外查询，并核对缓存密文逐字节不变。使用新缓存仓库读取同账号历史，确认磁盘仍可恢复。
- 所有学校响应、账号、密码及设备均为虚构；测试不会访问学校服务或注销真实设备。

## 本地检查

项目 Gradle Wrapper 的 Debug **533 项**、Release **493 项**单元测试全部通过，失败、错误和跳过均为 0。本次新增 5 项控制器回归，并更新原断网清空测试；Debug／Release Lint 为 0 错误、0 警告。Debug APK、设备测试 APK 及正式签名 Release APK 均构建成功，正式证书与 `release-signing.sha256` 一致。

Android 12／16 各 26 项不同的资费回归最终全部通过，包含生命周期 4 项、缓存存储及冷恢复接入 4 项、保留数据界面 5 项、原资费界面 9 项、网页登录弹窗 3 项与 WebView 1 项。最后仅修改的后台认证用例在两个系统各单独复测 1 项通过，其余已经通过的用例不无故重跑。本机正式包同版本覆盖，两系统各 2 项资料与界面检查均通过，四份原有资料文件摘要及首次安装时间不变。

首轮同一模拟器同时启动了两个不同包的 instrumentation，Compose 前台检查受到干扰，Android 12 完整隔离重跑通过。Android 16 模拟器其后退出，已按原 AVD 重新启动；只在指定隔离设备重新建立虚构资料，核对固定签名与旧正式版本后再验证覆盖，未使用真实账号或修改真实设备。

独立复测又发现旧后台认证用例的网络及服务前提不足：真实开关 WiFi 后，首次网络存在时 DHCP／链路属性仍可能变化，认证按设计取消。失败脱敏诊断为 `WiFi 已变化，请检查认证状态`，账号存储仍可用。测试现先等待这些可联网模拟器完成系统 WiFi 验证，再启动虚构认证，并确认真实服务已经进入认证器、同任务仍运行后才切后台；原监听、完成及资费保留断言保持，未固定延时或放宽断言。临时诊断只记录网络身份是否变化的布尔，不记录网络标识；这不是产品的新联网门槛。补齐前提后，两个系统各单项复测通过。原始日志保留于被忽略的 `local/release-v057-wifi/`。

## 验证边界

模拟器真实开关 WiFi 验证系统网络事件与 App 状态处理，学校查询使用虚构会话。它不代表真实校园网、自助服务网站或手机品牌组合已完成实测。已安装 v0.5.7／38 的用户在本修订发布后需要手动覆盖安装，App 内版本比较不会提示同版本修订。
