# 校园网三种标题关系复查

日期：2026 年 11 月 17 日。检查基于 `60df193` 的现有实现，认证逻辑沿用 v0.5.4／35。本轮未发现新的标题状态覆盖问题，仅纠正研究生课表文档中的旧 3 秒说明，并记录复查结果。

## 三种提示的关系

| 条件 | 课表标题 | 对认证任务的影响 |
| --- | --- | --- |
| 开始认证，尚未确认在线 | 正在登录校园网 | 请求正常执行 |
| 等待达到 3.5 秒，仍在认证且未确认在线 | 登录超时，约 1 秒后恢复课表标题 | 仅提示等待较久，继续认证，不自动重试 |
| 任意阶段确认在线 | 立即替换为校园网已连接，约 2 秒后恢复课表标题 | 已确认成功；请求清理完成前继续占用原任务槽 |
| 3.5 秒前快速失败 | 直接恢复课表标题 | 实际错误留在校园网连接页 |
| 超时提示已经结束，认证后来成功 | 再显示校园网已连接，约 2 秒 | 允许晚成功，不受已经结束的短提示限制 |
| 已确认成功，但另一端请求仍在清理 | 成功提示到期后恢复课表标题 | 不恢复正在登录或登录超时，不重复认证 |

因此，真正晚成功时允许出现“正在登录校园网 → 登录超时 → 校园网已连接”；已提前确认成功时，不应因为请求清理较慢再显示超时。实际文案为“校园网已连接”。恢复标题在今日视图为星期，整周视图为所选周次。

## 状态链核对

- `CampusLogin` 的已有认证状态、公共／宿舍登录后状态确认、宿舍 IPv4 联网确认及最终联网复核等成功路径均调用结构化 `confirmed` 回调；自动识别任一端确认在线后即发布成功，再取消并等待另一端清理。
- `CampusLoginController` 在确认回调及结果落地前复核原任务、取消状态与 WiFi。确认成功后保留该结果，迟到进度、普通失败、清理异常及认证期限不能将其降级；用户取消、换网、账号失效和服务停止仍可使旧任务失效。
- `CampusConnectionNotice` 使用 3500ms 等待、1000ms 超时提示和 2000ms 成功提示。成功分支优先，并取消等待及旧提示计时；同一任务的结果提示仅展示一次。
- `CampusConnectionTitle` 仅观察运行时的结构化标题状态，直接替换文字；不依赖中文错误文案，不保留旧等待或超时标题的淡出。
- 旋转、切页及进度变化不重置等待期限。尚未开始展示的结果等待课表可见且无遮挡后计时；后台完成后先确认当前 WiFi。取消导入确认框也参与遮挡处理。
- 今日和整周使用同一个标题组件，标题切换不改变课表、日期、按钮的布局占位。
