# 中间通透度卡片白底修复验证

日期：2026 年 11 月 26 日（上海时间）。

## 问题与复现

用户确认 100% 时白底已消失，但约 34% 以后、到 100% 之前仍有突兀白底。原 `Modifier.glass` 仅在 `glass.alpha == 0` 时移除系统 elevation 阴影，部分透明卡片仍使用同一阴影层。

先在旧产品代码上加入真实设备回归：保持照片、主题、文字、尺寸及位置一致，将通用卡片与“只绘制一次所选底色和原细边框”的参考画面对照。原实现在 Android 12／API 31 和 Android 16／API 36 均失败，浅色主题的 32%、34%、50%、66%、80%、98% 档位出现内部采样色差；100% 和深色主题未出现这次色差。截图可见内容区与内边距之间存在额外矩形明暗差，与用户反馈一致。

这里的正常半透明底色仍会随所选档位保留；问题是同一卡片内部额外出现一块不同明暗的矩形。

## 修复范围

- 普通通用卡片全部档位停用 Android elevation 阴影，使圆角卡片只按所选 alpha 统一填充一次；不设新的中间阈值。
- 保留原 `.7dp` 细外框、裁切、点击、间距和前景。100% 时继续完全移除填充、保留外框。
- 考试卡片、成绩卡片和学分汇总复用同一修饰符，因此一并修复；其他使用该通用表面的卡片保持相同规则。浅色默认档位也不再附加普通卡片原来的 6dp 阴影。
- 底栏等 `strong = true` 的独立不透明表面及其原阴影保持。效果预览本已采用单层填充，修复后真实卡片与该绘制方式一致。
- 透明度范围、步长、保存数值、照片遮罩、字体颜色、存储、版本和网络行为不变。

## Android 界面检查

Android 12／API 31 与 Android 16／API 36 最终各 **23 项**通过：`WallpaperTest` 15 项和 `AcademicDeviceUiTest` 8 项。

- 新增逐档回归覆盖 2%–100%、每档 2% 的全部 **50 档**，分别检查浅色和深色主题。每个组合在卡片内部选取 25 个分布于内容区及内边距的点，与同一位置的单层填充参考对照，每个 RGB 通道容差 1；每台共 **100 个主题／档位组合、2500 个采样点**通过。
- 新增实际考试与成绩页面回归覆盖 34%、66%、98%、100%，深浅主题及两页共 **16 个画面**，课程文字可见且无排版溢出。学分汇总、考试卡片和成绩卡片使用实际组件及虚构资料。
- 原 100% 整帧像素检查继续通过：内部与原背景一致、原细边框可见，外框之外无阴影像素；原设置保存、恢复默认、旋转、两倍字体、横屏及考试编辑等检查通过。
- 已查看 80% 同尺寸前后截图及浅色成绩、深色考试实际页面：内部矩形色差消失，细外框和正常单层半透明底色保留。

首轮 API 31 模拟器遗留 `640×1280／440dpi` 配置，逻辑宽度仅约 233dp，原横屏两倍字体检查失败；新增逐档与考试／成绩检查均通过。尝试设置 1080×2400 后，旧虚拟屏仍被限制为物理 320×640 的两倍。随后将该测试机设为 `640×1280／260dpi`（约 394dp 逻辑宽度），完整两类检查重跑 **23／23** 通过。API 36 使用 `1080×2400／440dpi`，**23／23** 通过。未修改或放宽既有断言。初次失败及重跑日志均保留。

上述检查针对模拟器、指定照片及采样位置，不代替用户手机或所有厂商 GPU 的实际验收；本次不涉及学校联网实测。
