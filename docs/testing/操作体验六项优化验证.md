# 操作体验六项优化验证

日期：2026 年 11 月 19 日。落实用户批准的前六项操作优化，版本保持 0.5.6／versionCode 37。本轮仅推送源码，不发布 Release，不修改版本标签、公开 APK 或更新元数据；当前公开 APK 尚未包含本批改动。校历继续暂缓。

## 实现行为

1. 课程和账号编辑按实际草稿判断修改。有修改时点击外部保留草稿，取消或系统返回以“放弃未保存的修改？”替换编辑框，可继续编辑或放弃；改回原值可直接退出，保存期间禁止退出。课程草稿沿用状态恢复，账号草稿只保留在 ViewModel 内存，旋转后继续，结束编辑或存储失效后清除，未保存的密码草稿不进入状态恢复或文件。
2. 已有课程真实编辑或删除成功后，以底部 Snackbar 提供短时撤销。通常显示 10 秒，遵循无障碍建议，旋转不重置剩余时间；新增或无变化不显示。后台、后续编辑或写入、切学期、导入、解绑及重新读取后失效。撤销前在仓库锁内复核当前资料及加密文件，恢复原 ID、课程顺序和全部安排，不能覆盖后续修改。
3. 已有账号无变化时禁用保存，并在 ViewModel 再次校验；备注和账号去首尾空白比较，密码逐字比较，清空原备注仍算修改。新增账号继续要求账号、密码有效。
4. 验证码键盘“完成”和“登录查询”共用有效性与忙碌校验，主动提交后隐藏键盘并清除焦点；同帧连点只触发一次，输入及加载不自动提交。
5. 恰好一台在线设备时，顶部“注销设备”直接进入该设备的原最终确认；多台仍先选择，零台禁用，确认前不发起注销。
6. 删除确认按实际去重安排显示周次、星期、节次及次数，默认仅本次，按钮显示“删除这 N 次安排”；空选择或没有匹配安排时不能提交，非连续节次不重复计数。

另外修复课程无变化保存仍重写学校时间说明、重排课程或学期的问题。相同内容保持原记录及密文，也不产生撤销。

## 审查修复复测

- 刚修改星期或学期周数时，系统返回读取最新草稿。新的回归用例把修改和返回安排在同一次主线程调用中，验证界面重组前也会询问是否放弃，继续编辑能看到修改值。
- 侧边手势超过系统触摸阈值后保留编辑器。回归用例在卡片外拖动后回到起点并松手，再验证未修改时一次普通外点仍可关闭编辑器。
- 若保存课程后先显示更新弹窗，撤销会等弹窗关闭后再首次显示并计时。集成测试使用虚构更新数据，停留在弹窗超过 10 秒，再关闭并点击撤销，同时核对界面状态与加密课表恢复到编辑前。

Debug 单元测试 433 项通过。Debug Lint、应用 APK 和设备测试 APK 构建通过。设备复测包含 CourseOperationUiTest、CourseEditorAppTest 和 UpdatePromptIntegrationTest。Android 12 通过 22 项，通知权限测试因系统版本不适用跳过。Android 16 通过 23 项。
