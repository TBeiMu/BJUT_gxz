# 资费查询结果提示验证

日期：2026 年 11 月 20 日。用户反馈“正在查询”结束后状态直接消失，要求明确显示查询成功或失败。本轮作为同一资费缓存修订，沿用“仍发布为 0.5.7”的授权，版本保持 0.5.7／38，保留固定签名及原标签，验证后再次替换同一 Release 的三个附件及中文说明。当前为检查及发布准备记录。

## 修复

- 普通查询与内置网页登录共用的成功路径此前使用 `result.notice.orEmpty()`；学校通常不提供附加提示，因此成功时清空了状态。现在 null、空串或纯空白提示统一回退“查询成功”，非空提示仍优先，例如“刷新未确认，显示网页数据”。
- 普通失败继续通过现有结构化失败标记在右上角显示“查询失败”，保留最近一次数据及成功时间。验证码、登录未确认、会话／身份异常和设备注销结果不改为笼统成功。读取历史缓存不产生本次成功提示。
- 沿用原固定状态区域，提示持续到下次查询或其他状态变化；不新增弹窗、自动消失计时、动画、持久记录或网络请求。自动与手动刷新触发条件保持。
- 审查发现取消边界：若先收到暂停 WiFi 监听，再执行离开前台，旧代码会先将 running 置为 false 并保留“正在查询”。暂停监听现将运行中提示改为“查询已暂停，请重查”，已有注销结果仍由原优先规则保护，迟到成功不能改写暂停状态。

## 检查范围

新增 2 项 JVM 测试：普通／网页登录成功分别覆盖 null、空串、纯空白和非空必要提示共 8 组；暂停监听先于离开前台时，两条查询路径的迟到成功均被丢弃。现有成功→失败→重试、缓存恢复及取消断言同步加强。

浅／深色设备用例沿用 360dp、正常及 1.8 倍字体，显式检查查询中→成功、失败→成功的文字可见及卡片／按钮位置不变；保留原失败提示、4dp 间距、旧数据与时间、无省略和真实绘制边界断言。

所有账号、密码、学校响应、数据及设备均为虚构，不提交学校凭据或注销设备；模拟器结果不代表真实校园网或所有手机组合验收。
