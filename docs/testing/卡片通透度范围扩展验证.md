## 问题与范围

用户反馈“卡片透明度”拉满至 16% 后变化仍不明显。原实现将真实通透度限定在 2%–16%，即卡片背景仍为 98%–84% 不透明；自选壁纸又叠有原有文字保护遮罩，因此呈现较轻。效果预览与实际卡片使用的数值一致，未发现滑杆未应用的问题。

## 首次 50% 扩展的行为与兼容

- 滑杆范围 2%–50%，每档 2%；快捷档位为“默认 4%／轻透 20%／通透 50%”。
- `wallpaper.json` 仍保存实际 `cardOpacityPercent`，允许 50–98，沿用 schemaVersion 1、原子写入与原默认值 96。旧配置和原有每个数值原样读取，不自动把旧 16% 提高为 50%。
- 默认外观、原推荐搭配、已选图片及模糊值的行为保持。保存失败恢复最近一次有效设置。
- 仅通用卡片的背景 alpha 变化，文字和图标保持不透明；底栏等强实色表面、强调色、课程颜色及照片底层遮罩不变。
- 原 2%–16% 范围的次级墨色保持；新增范围逐步将次级墨色向主墨色靠近，最大 30%。深浅主题及效果预览共用同一调色函数。
- 自选壁纸的图案与色差在高通透时更明显；原颜色背景本身接近纸白／深灰，视觉变化仍较柔和。

## 追加：100% 卡片统一透明修复

用户试装测试 APK 后反馈：周围已经透明，但中间仍有白色块，要求除文字外整张卡片统一透明。本节取代上文“100% 保留原描边与阴影”的行为，既有扩展和验证过程保留。

### 复现与修复

旧通用 `glass` 修饰符在卡片填充 alpha 为 0 后仍附加浅色主题的 Android elevation 阴影及两主题的细描边。实际图像出现中间与周围的明暗差，视觉上像内容区仍有一块白底。仅检查卡片 alpha 和两侧壁纸色差无法发现该问题。

先增加真实设备回归检查：在同一照片、同一位置和同一文字布局下，对照启用卡片装饰与完全不加装饰的整帧像素。旧实现在 Android 12／16 均复现失败：中心留白像素一致，但整帧不一致，截图可见内边距与内容区的矩形色差和卡片轮廓。

修复后，在 100%（`glass.alpha == 0`）时通用卡片仅保留原裁切，不附加底色、阴影或描边。效果预览的卡片也跳过背景及描边，前景内容照常绘制。其他通透度、原布局与点击、配置格式、默认值、照片及模糊值保持；底栏等原独立强实色表面沿用。
