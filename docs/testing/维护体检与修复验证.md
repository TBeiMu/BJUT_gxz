## 确认的问题及修复

### 1. 调课同时修改内容，目标可能被静默丢弃（P1）

学校课程原先只按来源、ID、日期及节次识别重复目标；自定义课程也会无条件按已有时段过滤新增目标。修改名称、教师或地点并调到已有安排的时段时，会删除原选中的安排，却丢失修改后的目标，界面仍显示保存成功。

学校课程现在同时比较名称、地点、教师后再去重；自定义课程仅在内容不变时合并相同目标。保留未选中的原安排、原有容量限制与同内容去重规则。`LocalCoursesTest` 新增三项回归，分别核对名称、地点、教师变化及同 ID 的其他课程系列，覆盖保存后独立解密重载、撤销及再次重载。

### 2. 未知晚节次误报当天课程全部结束（P2）

`todayStatus` 原先跳过没有作息时间的第 13 节以后课程，随后直接返回“今天的课都上完了”。现在仍有未知时间课程且没有可确认的进行中／下一节时，回退日期文案，不推测其时间。`SchedulePresentationTest` 覆盖仅有晚节次、已知课程结束但仍有晚节次，以及正常时段的对照。

### 3. 注销请求结果不确定时丢失“未确认”语义（P2）

设备注销调用遇到连接或响应异常时，原先显示普通连接／响应错误，无法区分服务器可能已处理的情况。现在仅在实际注销调用阶段将这两类错误显示为“注销未确认，请刷新核对”；不会删除设备、声称成功或自动重发。等待认证清理时的错误及明确会话失效仍保留原语义。`BillingControllerTest` 新增三项回归检查上述区分和单次调用。

### 4. 旧下载通知能够取消新的下载（P2）

原通知的取消动作没有任务标识，且不同下载共用 PendingIntent 身份。现在动作携带不可复用的下载许可，并以许可区分 PendingIntent；仓库对当前下载或已批准待启动许可再次核对，保护服务仍保留旧 owner 的窗口。界面主动取消及原有清理逻辑保留。

独立复审另发现旧取消／旧启动动作与新服务启动命令交错时的 `startId` 边界。空闲服务处理这两种过期动作时，使用 `stopSelfResult(startId)`，只结束对应启动，避免停止系统已排队的较新请求。五项通知测试覆盖旧许可、空许可、服务仍持旧 owner、通知身份和两种启动 ID 边界，使用虚构下载源。

### 5. 实体网络监听开始时可能漏失断网或换网（P2）

校园 WiFi、课表和更新三种监听原先先读初始网络快照再注册回调，窗口内失去的网络可能持续留在状态中。现在先注册、再取快照；课表及更新在普通和默认网络回调均注册后才读初始默认网络。快照及收集均由 `try/finally` 保证释放回调，实体绑定及选路优先级保持。

`WifiMonitorStartupTest` 六项及 `ScheduleNetworkStartupTest`／`UpdateNetworkStartupTest` 各八项，共 **22 项**平台替身测试覆盖掉线、替换为移动网络、默认网络变化、稳定／空快照、停止后释放、快照异常及部分注册失败释放。

### 6. 返回 App 后未应用新的系统动画设置（P2）

原 `rememberReducedMotion` 只在首次组合读取设置，之后修改系统动画开关不会更新，使用独立帧循环的加载标志可能继续运动。现在仅在前台监听该设置，返回前台重新读取，停止或销毁时解除监听并丢弃排队旧事件。`ReducedMotionTest` 覆盖前台关闭／恢复及后台修改后返回。蓝色小鸟与原开屏、加载图形设计保持。

### 7. 迟到重复启动使认证服务残留并阻挡后续认证（P1）

Android 16 整套回归捕获重复启动测试主体完成后，取消清理仍无法结束服务。现场只读服务记录显示已无前台状态，却仍 `startRequested=true`、`lastStartId=2`。代码复核确认：重复启动已被系统排队，但认证先结束，`stopSelfResult(1)` 无法停止已收到第 2 次启动的服务；第 2 个回调随后因 ID 等于旧 `ownedId` 直接返回，已取消的观察器也不会再收尾。残留的服务所有权会阻止后续认证。

修复将忽略启动命令的条件限定为服务仍实际承接当前运行任务且观察器有效，并处理迟到取消命令；旧 ID 仍由控制器的单次启动及取消校验拒绝，按最新启动 ID 收尾。`CampusLoginServiceStartTest` 五项回归覆盖结束后迟到启动、旧 owner 与新任务、已脱离服务但仍在清理时的启动／取消，以及运行中旧命令无害。明确检查清理期间不能再次启动认证、凭据只读取一次、认证流程只启动一次。

### 设备回归与既有测试维护

首轮 Android 12 全套 191 项中，176 项通过、10 项失败、5 项因系统版本／权限前提或可选联网检查跳过。Android 16 首轮运行到通知拒绝用例时，因测试内部撤销已授予权限而被系统终止，未把该次运行计为完整通过。

为区分产品回归和旧测试问题，从原始 `e06a1ce` 导出独立源码副本并构建对照包；Android 12 对照 40 项中，29 项通过、9 项失败、2 项条件跳过，其中 9 项与本轮首测相同：

- 课表标题生命周期夹具只写了加密文件，没有刷新应用级课表控制器；现在调用既有重载辅助方法并等待正确身份和完整课表。
- 个人页仍期待课表姓名、详情仍期待已按现产品规则移除的“课程详情／重叠课程”外层标题；现在分别验证账号备注与课表身份，以及实际详情容器、课程卡片和内容。
- 暂停测试时钟后用坐标点击尚在滑入的周次项；现在使用该节点的语义动作，确认目标周后继续原有动画位置、退出禁用和固定圆点断言。

后台导入通知用例首测另有首次启动等待超时，在上述原始提交对照组中通过。补充仅含虚构会话状态的诊断后，第二轮明确读到 `notice=ERROR`、`opens=0` 和存储阻断提示：其他测试经独立仓库清除磁盘后，运行时仓库缓存陈旧，生产存储保护正确拒绝不匹配写入。测试现在先重载再清理，并检查未阻断、绑定／完整课表／进度均空；未更改生产存储保护或放宽首周导入断言。

通知拒绝专项改为要求宿主在 instrumentation 启动前撤权，保留真实权限弹窗拒绝后继续下载及单次调用断言，并由独立权限组实际执行补验。

## 现场验证边界

本轮仅使用虚构账号、课程、页面和下载源；设备测试限项目独立模拟器。没有提交真实校园凭据、注销真实设备、导入真实学校课表或操作用户正式资料。

以下仍需现场专项确认，不作为本轮自动化已通过的结论：

- 公共／宿舍 WiFi 的真实认证及校园实际耗时。
- 学校 CAS 姓名补全、真实资费查询与设备注销。
- 真实学校课表登录、完整导入及学校页面变更兼容。
- 不同手机品牌的省电策略、长时间锁屏与实际触摸手感。
- 固定正式签名覆盖安装后的真实资料保留；本轮调试包与未签名 Release 构建不等同于该验收。
