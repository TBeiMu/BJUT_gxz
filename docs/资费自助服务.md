# 资费查询与在线设备

工小助 v0.4.8 正式版提供北京工业大学[计费系统自助服务](https://jfself.bjut.edu.cn/Self/dashboard)查询。用户已确认正式版主要功能可用，本页介绍当前操作与边界。

v0.5.7／versionCode 38 将账号管理与校园网连接合并到“我的 → 校园网”。本版已正式发布，以下按新版入口说明；历史 v0.5.6 及以前仍有“校园网账号”“校园网连接”两个入口。发布及核验见 [v0.5.7 验证](testing/v0.5.7验证.md)，历史验证记录保持原样。

## 查询

在“我的 → 校园网”的账号管理区选择默认账号，然后进入“资费”。首次进入可自动查询，底部可手动“登录查询”或“刷新资费”。接通校园网与登录资费网站是两个独立会话，不读取系统浏览器的 Cookie。

资费页的“管理账号”直接定位“校园网”的账号管理区；存储故障时，“处理账号存储”进入同一页的恢复卡。顶部返回与系统返回均回到资费，旋转后仍保留浏览位置与来源；连接设置默认折叠。校园网账号、认证和资费查询的网络及凭据规则保持。

v0.5.2 将查询状态放在右上方、“可用流量”卡片上方，与左侧账号文字共用 14sp 字号和 21sp 行高，直接显示“正在查询”“请填写验证码”“注销未确认，请刷新核对”等简短文字。加载动画与文字相隔 4dp，作为一组靠右排列，换行后的文字在组内左对齐。提示不提供点击展开或弹窗。提示区至少预留两行文字及加载标识的空间，大字体时按可用宽度提前增加行数；四张卡片的数值和单位也预留共同高度，提示变化与数据载入不会推动下方查询和管理按钮。此布局调整已合入 v0.5.2。

学校要求验证码时，填写本次图片中的四位验证码；提交前不会重新生成图片。自动登录未完成时，可选择内置网页登录：预填所选账号和密码，由用户点击登录；修改本次密码不会写回账号存储。返回、切账号、切网或离开前台时清除临时会话。

用户随后反馈断开 WiFi 后资费立即清空，网络保留修复已按同一授权，于当日 14:45:21（上海时间）再次替换 v0.5.7／38 三个附件并完成公开核验。以下网络变化规则已包含在当前公开 APK 中；Android 12／16 隔离模拟器各通过公开包覆盖、界面及手动更新 3 项，四份资料摘要、内容及首次安装时间不变。此前 13:29:37 修订与实际核验事实保留在上述验证记录中，已安装同版本仍需手动覆盖安装。

普通查询失败时，四项资费、设备显示信息和查询时间继续使用上一次成功结果，标题区提示“查询失败”；失败不会把旧时间改成本次时间，没有成功数据时仍显示未获取。学校要求验证码、登录未确认及设备注销已确认／未确认等必要提示沿用原流程。

本机最多保存一条成功查询快照，按当前本机账号 ID 匹配读取，内容为四项指标、设备显示信息及原查询时间。冷启动可先显示该账号的缓存。同一账号断开、重新连接或切换 WiFi 后，最近结果和磁盘缓存也保留；网络变化仍取消原查询、清除 Cookie／验证码／网页登录等临时会话并禁用设备注销，旧网络迟到结果不能覆盖新状态。恢复及网络变化后保留的信息只供查看，只有新查询成功取得当前设备信息后才允许注销；设备记录不表示实时在线。

首次进入、返回前台及手动“登录查询／刷新资费”的原有规则不变，不因重连或切换 WiFi 增加自动尝试，不增加后台查询或失败凭据重试。切换或编辑账号、账号存储不可用、学校返回账号不符或明确会话失效时仍清除旧展示并失效缓存，保持本机账号 ID 隔离；注销提交前也先失效旧缓存。

缓存使用独立 Android Keystore 密钥和 AES-GCM 加密，原子保存在排除系统备份的 `billing-cache.vault` 中；不建立历史或按账号分散保存。密文上限为 32KiB，最多 64 台设备，各显示字段有长度限制。Cookie、验证码、网页登录会话、HTML、密码、服务器原始提示及真实设备注销标识均不保存；恢复设备使用合成标识，设备读取失败仅保留固定错误类别。超过上限或保存失败时保留原缓存，查询本身仍可成功；损坏、读取失败或缓存密钥不可用时忽略缓存，不影响有效账号及后续查询。

## 四项资费与设备

| 卡片 | 数据来源 |
| --- | --- |
| 已用流量 | 学校当前计费周期的已用值及单位 |
| 可用流量 | 学校返回的剩余值或“不限量”等文本 |
| 消费保护 | 学校返回的设置或金额 |
| 账户余额 | 学校返回的金额，保留小数精度 |

缺失字段显示“—”或“未获取”，不编造零值。页面保留账号摘要、查询时间和必要错误，不常驻诊断或技术说明。离开前台保留上次数值和时间，但清除 Cookie；同账号网络变化及账号切换的处理按上节规则执行。

在线设备显示 IPv4／IPv6、MAC、登录时间、在线时长和使用流量。同一会话的重复 IPv6 行合并，流量不累计。设备列表读取失败明确提示，不能显示成“没有设备”。

2026 年 11 月 11 日只读核对学校流量列：对 `downFlow`、`upFlow` 分别取整数，相加后除以 1024，显示 MB 和三位小数。缺失、负数、异常或重复行冲突时显示“未获取”，不使用账户总流量代替设备流量。

## 注销设备

1. 点击单台设备的“注销”，或底部“注销设备”后选择一台。
2. 核对设备信息与学校提示，确认后提交一次下线操作。
3. 学校确认后刷新在线列表；若断网、响应丢失或格式异常导致结果未确认，先重新查询核对，避免重复操作。

注销前先停止并等待进行中的校园认证清理。注销本机后本次前台期间不自动重新登录，需要时在“我的 → 校园网”顶部连接卡手动恢复。学校无感知认证可能自行重连，App 不代替用户关闭无感知、解绑 MAC 或批量踢设备。

v0.5.7 对实际注销调用的连接／响应异常明确显示“注销未确认，请刷新核对”，不会误报成功、从列表删掉设备或自动重发。请求尚未发出时的错误与明确会话失效仍单独处理；注销已确认但刷新失败时保留已确认结果。

## 网络与会话

资费请求仅通过当前实体 WiFi 访问 `https://jfself.bjut.edu.cn`，保留平台 TLS 校验，不转用移动数据。凭据只发往已识别的同源登录接口，失败后不自动重发。查询 Cookie、验证码和动态校验字段仅在内存保留。

登录读取实际页面地址及动态字段，隐藏验证码也先初始化同一会话；返回登录页而无明确错误时提示状态未确认，不直接判定密码错误。内置页使用限定来源消息接口，只接受当前会话、已校验表单的提交；禁止跨站导航及网页内注销设备。查询完成前核对返回账号与所选账号一致。

接口为 `dashboard/getOnlineList`、`dashboard/getOfflineTip`、`dashboard/tooffline`；下线参数由选中会话取得，禁止自动跳转、批量操作和重发。原始登录态页面可能内嵌密码和个人信息，不保存为测试样本或日志。
